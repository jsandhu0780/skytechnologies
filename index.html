What I do

      
Four kinds of infrastructure problem

      
Most of the work falls into one of these, and the interesting projects touch all four at once.

    

    

      

        
multicloud

        
Architecture on AWS and Azure

        
Cloud-native environments designed for availability and fault tolerance rather than assembled by default — landing zones, network topology, identity, and the boundaries between workloads.

      

      

        
automation

        
Infrastructure as code and CI/CD

        
Environments defined in Terraform and CloudFormation, deployed through pipelines in Azure DevOps, Jenkins, or CodePipeline. If a change is made by hand, it isn't finished.

      

      

        
hybrid

        
On-prem that still has a job to do

        
vSphere estates, storage, and physical networking kept healthy alongside cloud — including the migrations where workloads move up and the ones where they stay put for good reasons.

      

      

        
operations

        
Cost, performance, and security

        
Monitoring that catches problems before users do, tuning that keeps latency flat, and spend reviews that cut cloud bills without quietly trading away resilience.

      

    

  







  

    

      
Technical depth

      
The stack, ground to sky

      
Read it from the bottom up — that's also the order I learned it in, starting in a server room and working upward.

Physical hosts, power and cooling, capacity planning, and the on-call rotations that keep thousands of servers answering.

  • Bare metal
  • Capacity planning
  • Hardware triage

Virtualization L02

        
The abstraction that made everything above it possible — clustered hypervisors with high availability, fault tolerance, and tested recovery.

        
  • VMware vSphere
  • ESXi
  • vCenter
  • Site Recovery Manager
  • Storage & SAN

      


      

        
        
Cloud platforms L03

        
Enterprise workloads architected across two providers, with the networking and identity design that decides whether the rest of it holds together.

        
  • AWS
  • Microsoft Azure
  • VPC / VNet design
  • IAM
  • Cost optimization
  • Migration

      


      

        
        
Automation L04

        
Infrastructure declared in code and shipped through pipelines, so environments are reproducible and every change has a commit behind it.

        
  • Terraform
  • CloudFormation
  • Azure DevOps
  • Jenkins
  • AWS CodePipeline
  • Git / BitBucket

      


      

        
        
Platform & visibility L05 · sky

        
Where applications actually live now, and the instrumentation that makes their behaviour legible at three in the morning.

        
  • Kubernetes
  • Docker
  • Datadog
  • CloudWatch
  • Azure Monitor

Background

        
Cloud engineering, learned from the ground floor

        
I'm Jashan Sandhu, a Senior Systems Engineer based in Brampton, Ontario. I design, deploy, and operate cloud infrastructure across public and private platforms — and because I started in a datacenter rather than a console, I tend to know what the abstraction is actually sitting on.

        
That path runs through hardware operations, VMware estates, and integration work before it reaches multicloud architecture, which is why hybrid environments hold no mystery for me. Most organizations aren't purely cloud or purely on-prem; they're mid-migration, indefinitely, and the engineering that matters happens at the seam.

        
Alongside the technical work I spend a lot of time translating it — turning architecture decisions into terms a stakeholder can weigh, and staying the point of contact between the technical and business sides of a project. Sky Technologies is where I collect that work.
